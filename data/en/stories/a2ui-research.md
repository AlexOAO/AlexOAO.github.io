## Results

**I am taking the A2UI research down a "technology to product" path: find business use cases first, then confirm resources, then prove business value, and only then talk about launch.** It is now in phases 1 and 2: candidate use cases are mapped, and the environment and resources for the PoC, a proof of concept, are being confirmed. The next gate is the business-value checkpoint.

## Why this project

A2UI lets an AI Agent reply not just with text but with a screen. It is a protocol (a shared set of rules for how systems talk) that Google open-sourced in December 2025: the Agent sends JSON data saying which components to show and what data goes in them, and the front-end screen draws it using its own pre-approved components. Because the Agent sends data, not code, it cannot run arbitrary programs; it can only pick from the front end's list of components.

For a bank, this solves a real problem. Wealth information in a long block of text is hard for customers to read, but letting AI write web code directly would never pass a security review. A2UI sits in between: **the AI decides how the screen is laid out; the bank decides which components exist.**

## My role

I lead this research. The question I have to answer: can this technology become a feature in the bank's products?

## What I did

**Phase 1 | Business use cases.** When you research a technology, the first question is not "what can it do" but "where can we use it". With the Wealth Assistant as the main case, I mapped three candidates:

- Asset overview: cards and charts that show a customer's asset allocation, instead of a long text.
- Product comparison: a comparison table of the funds a customer asks about.
- Data entry: forms that help a customer fill in things like the risk profile questionnaire.

I also had to draw the line first: under the pre-launch check, the Wealth Assistant may not make transactions, so A2UI is used only to show information and fill in data, with no order buttons.

**Phase 2 | Resources.** I listed what the PoC needs: environment requirements and technical specifications, applications for Azure AI Foundry and tokens, connection to the IT test environment, and the list of front-end components allowed. What A2UI can draw depends on which components the bank approves. In progress.

**Phase 3 | Value check.** Being technically possible is only the starting point. At the checkpoint, the business units must confirm: which use case is most worth doing first, and which metric tells us it succeeded?

**Phase 4 | PoC.** Once a use case is chosen, build it in the test environment and apply the Guardrails and pre-launch checks. Screens generated by an Agent must pass the same checks as anything else the AI produces.

**Phase 5 | Productize.** After the PoC passes, work with the Wealth Assistant team to put A2UI on the product roadmap.

## Next steps

- Finish confirming resources, and get ready to explain the business value at the checkpoint.
- Agree the first use case to launch with the Wealth Assistant team.
