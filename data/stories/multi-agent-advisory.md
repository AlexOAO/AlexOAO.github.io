## 結果

**我們讓五個 AI Agent 像基金團隊一樣分工、互相辯論，再用 Zipline 這套回測工具，拿台股歷史資料模擬了三年的交易。** 具體績效不能公開，但結果讓團隊對這個架構行得通有了信心。

## 為什麼要做

一個人做投資決策容易有盲點，所以基金公司會設置不同角色的分析師。單一 LLM 也一樣：它很難同時兼顧技術面、新聞情緒和基本面，給的建議也看不到推理過程，沒辦法檢驗。那如果讓 AI 也分工呢？

## 我的角色

我負責架構協作：設計每個 Agent 的分工，並用 MCP 工具接上 TEJ 的數據。MCP 是一種標準介面，讓 AI 能呼叫外部的工具和資料。

## 我怎麼做

**第一階段｜需求分析。** 我們要解決單一 LLM 的兩個問題：顧不全技術面、新聞情緒和基本面；建議背後也沒有可以檢驗的推理過程。

**第二階段｜設計。** 五個 Agent 各做一件事：技術分析師算技術指標、判斷趨勢；新聞情緒分析師把市場情緒變成分數；基本面分析師看財報、評估公司價值；多空辯論員整合大家的觀點，正反兩方辯論；交易員根據辯論結論，給出買或賣的訊號。框架我們比較了 CrewAI、AutoGen 和 LangGraph，最後選 LangGraph，因為在金融場景裡，「可控」比「讓 AI 自己決定」更重要。Agent 之間怎麼傳資料、遇到什麼條件走哪條路、出錯怎麼處理，都能用流程圖清楚定義。

**第三階段｜開發。** 這套系統不只是聊天，而是根據數據做決策。透過 MCP，每個 Agent 都能直接呼叫 TEJ API 拿數據。

**第四階段｜驗證。** 我們把交易訊號接進 Zipline 回測引擎，用台股歷史資料檢驗三年的表現。

## 我學到的事

Multi-Agent 系統最大的挑戰，不是讓每個 Agent 更聰明，而是設計好它們之間的「溝通規則」：誰先發言、誰做最後決定、意見衝突時怎麼辦。這些流程設計，決定了系統的上限。更多細節在這篇文章：[Multi-Agent 投資決策架構](posts/multi-agent-investment.html)。
