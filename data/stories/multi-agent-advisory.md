## 結果

**我們讓五個 AI Agent 像基金團隊一樣分工、辯論，並用 Zipline 在台股歷史資料上跑了三年回測。** 具體績效不能公開，但結果讓團隊對這個架構的可行性有了信心。

## 為什麼要做

單一 LLM 和一個人做投資決策一樣，容易有盲點。所以基金公司會設置不同角色的分析師。單一 LLM 很難同時處理技術面、新聞情緒與基本面，給出的建議也缺少可以檢驗的推理過程。那如果 AI 也分工呢？

## 我的角色

我負責架構協作：設計 Agent 的分工，並整合 MCP 工具串接 TEJ 數據。MCP 是讓 AI 呼叫外部工具與資料的標準介面。

## 我怎麼做

**第一階段｜需求分析。** 單一 LLM 很難同時處理技術面、新聞情緒與基本面，給出的建議也缺少可以檢驗的推理過程。

**第二階段｜設計。** 五個 Agent 各司其職：技術分析師計算技術指標、判斷趨勢；新聞情緒分析師量化市場情緒；基本面分析師分析財報、評估價值；多空辯論員整合觀點、正反辯論；交易員根據辯論結論產出買賣訊號。框架我們比較了 CrewAI、AutoGen 和 LangGraph，最後選 LangGraph。因為在金融場景，可控性比自主性重要。Agent 之間怎麼傳資料、條件怎麼分支、錯誤怎麼處理，都能用流程圖清楚定義。

**第三階段｜開發。** 系統不只是在聊天，而是根據數據做決策。透過 MCP，每個 Agent 都能直接呼叫 TEJ API 取得數據。

**第四階段｜驗證。** 把訊號接進 Zipline 回測引擎，用台股歷史資料驗證三年的表現。

## 我學到的事

Multi-Agent 系統最大的挑戰，不是讓每個 Agent 變聰明，而是設計好它們之間的「溝通協議」：誰先說話、誰有最終決定權、衝突怎麼解決。這些流程設計，決定了系統的上限。更多細節在這篇文章：[Multi-Agent 投資決策架構](posts/multi-agent-investment.html)。
