## 結果

**我替 AI 營運成效 Dashboard 設計了一套指標框架，分成五個面向：採用、品質、效益、成本、風險。** 同一套框架，可以同時用在行內員工用的 Copilot、Gemini、艾拉小幫手，以及服務客戶的四個 Agent。

Dashboard 目前還在規劃：AI ROI（投資報酬率）的衡量指標正在設計，Copilot 營運月報要先和 IT 確認手上有哪些資料。

## 為什麼要做

銀行的 AI 已經分成兩條線在跑：給員工用的（對內）和給客戶用的（對外）。對內，Copilot 正在擴大試用，25 個處室都已申請，共 771 套。Gemini 訓練快要開課，艾拉小幫手則還沒有可以看營運狀況的儀表板。對外，四個 Agent 正準備上線。

每條線都有自己的數字，卻沒有一張表能回答主管最在意的問題：**這些 AI 投資，到底值不值得？**

## 我的角色

協作。我參與設計指標框架，並規劃把四個 Agent 的成本模型和 Guardrails PoC 的測試結果，接到同一張 Dashboard 上。

## 我怎麼做

**第一階段｜問題定義。** 一張 Dashboard 只需要回答一個問題：這筆 AI 投資值不值得？

**第二階段｜框架設計。** 要回答這個問題，需要看五個面向：

- 採用：有沒有人在用？看授權數、啟用率、活躍使用者、有多少部門在用。
- 品質：用得好不好？看回答正確率、轉給真人處理的比例、使用者回饋。
- 效益：省下什麼、多了什麼？看省下的工時，以及處理量、轉換率這類業務數字。
- 成本：花了多少？看授權費、Token 用量（模型處理了多少文字）、GPU 用量。
- 風險：安不安全？看護欄該擋卻沒擋的比例（漏放率）、不該擋卻擋了的比例（誤擋率），以及異常事件。

採用和品質，回答的是「有沒有在用」；效益、成本和風險，才回答「值不值得」。四大 AI 專案和新專案的 AI ROI 衡量指標，正照這個框架設計，回應 DDT 的要求。

**第三階段｜資料蒐集。** 對內工具的使用數據，原廠報表本來就有。Microsoft 的 Copilot Dashboard 有準備度、採用、影響和使用者感受四類指標；Google Workspace 的 Gemini 報表有授權數、活躍使用者和使用趨勢。艾拉小幫手是行內自己做的，要等資訊處開通後台權限、提供原始資料，才能分析。對外的四個 Agent，指標要連到業務成果：貸款助理看轉換率，智能徵審看處理量，客服助理看服務成本，智富管家看活躍度和 AUM（客戶交給銀行管理的資產規模）。成本沿用四個 Agent 的成本模型；風險沿用 Guardrails PoC 測出的漏放率和誤擋率。

**第四階段｜試行。** 和 IT 確認 Copilot 現有的資料後，再討論 Agent 管理和業務指標，做出第一份營運月報。

**第五階段｜制度化。** 長期來看，這些指標會成為商銀 AI 營運平台裡「AI 營運分析（品質／成效／資產）」的一部分。

## 下一步
