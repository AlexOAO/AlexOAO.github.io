## 結果

**我為 AI 營運成效 Dashboard 設計了一套五個面向的指標框架：採用、品質、效益、成本、風險。** 同一套框架，同時適用對內的 Copilot、Gemini、艾拉小幫手，以及對外的四大 Agent。

目前 Dashboard 還在規劃階段：AI ROI 衡量指標正在設計，Copilot 營運月報要先和 IT 確認現況資料。

## 為什麼要做

銀行的 AI 已經分成兩條線在跑。對內，Copilot 正在擴大試用，25 個處室全數完成申請、共 771 套；Gemini 訓練即將開課；艾拉小幫手則缺少營運儀表。對外，四大 Agent 正準備上線。

每條線都有自己的數字，卻沒有一張表能回答主管最在意的問題：**這些 AI 投資，到底值不值得？**

## 我的角色

協作。我參與指標框架的設計，並規劃把四大 Agent 的成本模型與 Guardrails PoC 的測試結果，接進同一張 Dashboard。

## 我怎麼做

**第一階段｜問題定義。** 一張 Dashboard 只要回答一個問題：這筆 AI 投資值不值得？

**第二階段｜框架設計。** 要回答它，需要五個面向：

- 採用：有沒有人在用？授權數、啟用率、活躍使用者、部門覆蓋率。
- 品質：用得好不好？回答正確率、轉人工率、使用者回饋。
- 效益：省了什麼、多了什麼？節省工時，以及處理量、轉換率這類業務指標。
- 成本：花了多少？授權費、Token 用量、GPU 卡秒。
- 風險：安不安全？護欄的漏放率與誤擋率、異常事件。

採用和品質，回答的是「有沒有在用」；效益、成本與風險，才回答「值不值得」。四大 AI 專案與新專案的 AI ROI 衡量指標，正在依這個框架設計，回應 DDT 的要求。

**第三階段｜資料蒐集。** 對內工具的採用數據，原廠報表就有：Microsoft 的 Copilot Dashboard 提供準備度、採用、影響與使用者感受四類指標；Google Workspace 的 Gemini 報表提供授權數、活躍使用者與使用趨勢。艾拉小幫手是行內自建，要等資訊處開通後台權限、提供原始資料，才能分析。對外的四大 Agent，指標要接到業務成果：貸款助理看轉換率、智能徵審看處理量、客服助理看服務成本、智富管家看活躍度與 AUM；成本沿用四大 Agent 的成本模型，風險沿用 Guardrails PoC 的漏放率與誤擋率。

**第四階段｜試行。** 和 IT 確認 Copilot 的現況資料後，討論 Agent 管理與業務指標，產出第一份營運月報。

**第五階段｜制度化。** 長期來看，這些指標會成為商銀 AI 營運平台中「AI 營運分析（品質／成效／資產）」的一部分。

## 下一步

- 確認每個資料來源實際拿得到哪些欄位，先做出對內工具的第一版 Dashboard。
- 為每個指標訂出目標值，讓 Dashboard 不只顯示數字，也能顯示「達標了沒」。
