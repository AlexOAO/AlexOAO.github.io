## 結果

**我把四個成本結構不同的 Agent，放進同一套管理機制：上線前先寫下業務量、成本與效益的基準，上線後用比率追蹤基準實現了多少。**

- 完成共同的成本效益衡量框架。四個 Agent 第一次能在同一張表上比較。
- 定義兩類可觀測的指標：業務比率，看 AI 實際承接了多少業務；實現比率，看當初的預估有沒有兌現。
- 各 Agent 的基準正在建立，請看下面的子專案。

## 為什麼要做

四大業務服務 Agent 準備上線，銀行要決定資源先給誰。只看建置成本做不了這個決定：有的 Agent 成本在地端，有的在雲端，效益也各自用不同的語言描述。更大的問題在上線之後：如果沒有人回頭檢查預估有沒有實現，評估報告就只是一份申請文件。

## 我的角色

我主責成本效益框架與管理機制的設計。業務量與效益由各業務單位（BU）提供，框架、計算與比較由我負責。

## 我怎麼做

**第一階段｜問題定義。** 四個 Agent 的成本結構完全不同。要放在同一張表上比較，第一步是找出共同的衡量方式。

**第二階段｜框架設計。** 我用同一組公式描述所有 Agent：成本＝業務量 × 單件資源用量 × 資源單價；效益＝業務量 × 單件效益 × 價值單價。兩邊都從業務量出發，所以可以直接得到可比較的單件成本與 ROI。在這個框架上，我定義兩類可觀測的指標：

- 業務比率：AI 承接的業務 ÷ 總業務量，例如 AI 處理率、自動完成率、轉人工率。它回答「AI 有沒有真的在做事」。
- 實現比率：實際值 ÷ 基準值，例如業務量實現率、成本執行率、效益實現率。它回答「當初的預估有沒有兌現」。

**第三階段｜資料蒐集。** 業務量與效益由各 BU 提供，技術規格由廠商提供。目前正在收回。

**第四階段｜試算。** 用收回的資料，為每個 Agent 建立三年的業務量、成本與效益基準。這份基準，就是上線後計算實現比率的分母。目前正在進行。

**第五階段｜制度化。** 規劃把指標接進資源配置的流程：上線前提出基準，上線後定期追蹤業務比率與實現比率；實現比率低於門檻時，啟動檢討，調整資源或範圍。
