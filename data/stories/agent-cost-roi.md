## 結果

**我把四個成本結構完全不同的 Agent，放進同一個經濟公式：事件數量 × 每個事件消耗的資源 × 資源單價。** 貸款助理、智能徵審、客服助理、智富管家，第一次能在同一張表上比較。

- 完成三套成本模型（容量、地端攤提、雲端 Token）與一套效益模型。
- 完成算力池模型與尖峰估算，以及給四家廠商的資料索取表。
- 建立四大 Agent 三年 TCO、TBE 與 ROI 的比較表格式。每個 Agent 的試算，請看下面的子專案。

## 為什麼要做

四大業務服務 Agent 準備上線，銀行得決定 GPU 怎麼分、預算怎麼編。問題是它們的成本長得完全不一樣：有的吃地端 GPU，有的燒雲端 Token，有的只用 CPU。沒有共同的模型，就沒辦法比較，也沒辦法決定資源該先給誰。

## 我的角色

我主責成本模型與三年 TCO／ROI。業務量與效益由各業務單位（BU）提供，模型設計、計算與比較由我負責。

## 我怎麼做

**第一階段：把 GPU 拆成空間和時間。** 我用一棟大樓來說明算力中心：樓板面積決定能進駐多少 AI 模型，營運工時決定能服務多少 Agent。空間是 GPU 記憶體，放模型，佔了就不還，是固定成本；時間是 GPU 算力，跑請求，用完重來，是變動成本。本行的算力池是 5 張 RTX PRO 6000，每張 96 GB，合計 480 GB、每日 432,000 卡秒。

**第二階段：建立三套成本模型與一套效益模型。** 容量模型算出每個 Agent 的地端元件需要多少記憶體與卡秒；地端攤提模型讓共用元件只算一份，依時間佔比分攤；雲端 Token 模型是「業務量 × 每段旅程的 Token × 單價」；效益模型是「業務量 × 單位效益 × 價值單價」。建空間模型時有一個關鍵：KV 快取占用的記憶體，取決於「同時處理幾件」，而不是「一天處理幾件」。所以要不要加購 GPU，看的是尖峰時刻有多少人同時在用。

**第三階段：算力池與尖峰估算。** 我把四個 Agent 的元件放進 5 張卡的算力池，估算尖峰時段的佔用，並設計廠商資料索取表，只向四家廠商索取地端元件的規格：模型大小、量化格式、每字佔用、同時件數，並要求附上代表性的測試樣本。

**第四階段：AI Agent 算力估算。** 目前正在進行，等廠商回填規格後收斂。

## 下一步
