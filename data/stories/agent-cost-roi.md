## 結果

**我替四個業務服務 Agent 各建立了一個專案原型，再用同一套機制衡量它們的成本與效益。** 原型讓業務單位在投入大筆預算之前，先看到 Agent 實際怎麼運作；成本效益機制讓四個 Agent 第一次能放在同一張表上比較，上線後也能追蹤預估有沒有兌現。

- 四個原型，分別對應客戶旅程的四個階段：獲客、交易、服務、經營。
- 一套共同的成本效益框架，以及兩類可觀測的指標：業務比率與實現比率。
- 各 Agent 的基準正在建立，詳情請看下面的子專案。

## 為什麼要做

銀行的目標，是用 AI Agent 把客戶的整段旅程串起來：從第一次接觸、申辦、使用服務，到長期的財富經營。每一段由一個 Agent 負責，四個 Agent 共用客戶資料，彼此的成果再回饋到下一段。

但四個 Agent 的服務對象、部署方式與成本結構都不一樣。要決定資源先給誰，就要先回答兩個問題：它實際會怎麼運作？它值不值得？

## 四個 Agent 與客戶旅程

**第一段｜智慧獲客：[貸款助理（Sales Agent）](project.html?id=agent-loan-assistant)。** 目標是精準觸達、提升轉換。它在數位申辦平台與社群上直接和客戶對話：說明產品、引導申辦，並在授權範圍內議價。超出授權的條件轉給主管，它不能承諾核貸結果。它在授權範圍內自主運作，由人處理例外（human-on-the-loop）。部署在雲端，資料送出前先去識別化。

**第二段｜智慧交易：[智能徵審（Credit Agent）](project.html?id=agent-credit-review)。** 目標是快速核貸、提升效率。它不面對客戶，而是幫徵審人員辨識財力文件、檢查內容是否合理、計算年收，每個判斷都附上理由。信心不足的案件轉給徵審人員，它不產生授信決策或評分。每一件都由人覆核（human-in-the-loop）。雲端與地端混合，在離峰時段批次處理。

**第三段｜智慧服務：[客服助理（Service Agent）](project.html?id=agent-customer-service)。** 目標是主動服務、提升滿意度。它是客服人員的 Copilot：查知識庫、擬回覆草稿、寫話後小結、做質檢初判。寫進紀錄的內容都要人員確認，它不直接回覆客戶（human-in-the-loop）。因為處理通話錄音，全部部署在地端。

**第四段｜智慧經營：[智富管家（App 2.0）](project.html?id=agent-wealth-assistant)。** 目標是財富管理、深化價值。它是 App 裡的理財對話：查詢帳務、分析資產、說明商品。推薦之前必須先確認客戶的風險等級，它不執行交易，也不碰密碼與驗證碼（human-in-the-loop）。雲端與地端混合：地端的小型模型判斷意圖，雲端的模型處理查詢。

## 閉環：四個 Agent 怎麼串起來

- **同一個客戶，同一份資料。** App、網銀與分行的客戶資料整合在一起，不管客戶從哪個通路進來，Agent 認得的都是同一個人。
- **決策中樞。** 交易資料加上和 Agent 的互動記憶，形成客戶 360 的樣貌，再由傾向模型判斷下一步適合提供什麼。
- **回饋。** 每一段的結果回到資料裡，持續優化，創造下一次商機：獲客帶來的客戶進入交易，交易後的服務與經營再帶出新的需求。
- **共同的基礎。** 四個 Agent 共用集團的算力、AI 營運管理平台與 AI 治理。上線前的檢核見 [AI 治理](project.html?id=agent-governance)，上線後的成效見 [AI 營運成效 Dashboard](project.html?id=ai-ops-dashboard)。

## 我的角色

我做了兩件事：

- **建立原型。** 四個 Agent 各做一個專案原型，讓業務單位看得到、用得到，再決定要不要投入。
- **主責成本效益。** 設計四個 Agent 共用的成本效益框架與管理機制。業務量由業務單位提供，用量由資訊單位提供，框架、計算與比較由我負責。

## 我怎麼做

**第一階段｜原型。** 依每個 Agent 的場景建立原型，把「它會怎麼運作」變成看得到的東西。例如智富管家的原型是一個行動網銀 MVP，從登入、帳務查詢到 AI 對話都能實際操作。

**第二階段｜框架設計。** 四個 Agent 的成本結構完全不同：有的在雲端，有的在地端；有的按通話計，有的按案件計。我用同一組公式描述它們：成本＝業務量 × 單件資源用量 × 資源單價；效益＝業務量 × 單件效益 × 價值單價。兩邊都從業務量出發，所以可以直接得到可比較的單件成本與 ROI。在這個框架上，我定義兩類指標：

- 業務比率：AI 承接的業務 ÷ 總業務量，例如 AI 處理率、轉人工率。它回答「AI 有沒有真的在做事」。
- 實現比率：實際值 ÷ 基準值，例如業務量實現率、成本執行率、效益實現率。它回答「當初的預估有沒有兌現」。

這套三年基準，適合規模大、成本結構複雜的 Agent。數量多、規模小的內部需求，則用比較輕的評分表排序：效益、可行性、合規與成本，各由 BA 或 SA 填寫。兩者互補：大型 Agent 先算清楚值不值得，小需求先排出先後順序。

**第三階段｜資料蒐集與試算。** 業務單位提供業務量與效益，資訊單位提供用量。資料到齊後，為每個 Agent 建立三年的業務量、成本與效益基準。這份基準，就是上線後計算實現比率的分母。目前正在進行。

**第四階段｜制度化。** 規劃把指標接進資源配置的流程：上線前提出基準，上線後定期追蹤業務比率與實現比率；實現比率低於門檻時啟動檢討，調整資源或範圍。
