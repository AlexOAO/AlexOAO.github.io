## 結果

**FinCLI 每天收盤後自動抓取台股原始資料，寫進 PostgreSQL；Vibe-Edge 的資料層從這裡讀資料。** 核心是 `tw-fin-scraper` 這個命令列工具。它目前有 23 個來源模組，包括證交所、櫃買中心、公開資訊觀測站（MOPS）、TEJ 與期交所。

## 為什麼要做

量化研究需要原始、可以追溯的資料，但很多台股資料沒有現成的 SDK 套件可用。例如處置股、注意股、法說會與三大法人買賣超，都只能逐一串接官方 API 或網頁。

我也定了一條規則：抓取層不轉換資料。來源給什麼就存什麼，清洗交給下游。如果抓取時擅自轉換，下游就拿不回原始數字。

## 我的角色

獨立開發 `tw-fin-scraper` 與 `yf-history`。

同一個資料夾裡的 QuantaAlpha 不是我寫的。它是外部的開源專案（[QuantaAlpha/QuantaAlpha](https://github.com/QuantaAlpha/QuantaAlpha)），沒有放進 FinCLI 的版本控制。我只改了兩個設定檔，把它指向台股資料，跑了一次基準測試。

## 我怎麼做

**第一階段｜先拿到資料。** 先用 yfinance 回填 51 檔台股，2019-09-02 到 2026-08-31，共 1,699 個交易日，存成原始 CSV。另外串接證交所 T86 三大法人買賣超。回填時遇到來源限速，我把 HTTP 428 也當成 429 處理，用指數退避的方式，等待時間逐次拉長後再重試。

**第二階段｜擴大來源並落地資料庫。** 一次新增 8 個資料來源，PostgreSQL 擴大到 26 張表，並加上 `--resume` 中斷後續抓。證交所官方 OpenAPI 的 143 個端點全部串到，櫃買中心的 225 個 OpenAPI 端點也全部串到。TEJ 則以瀏覽器自動化登入，把 238 張表的快照存成底稿。

**第三階段｜用規格取代手寫程式。** 我刪掉約一萬行手寫程式，改用「規格檔 + 通用引擎」。證交所 141 個 OpenAPI 資料型別，原本是一個一個手寫的。切換前，我先確認新舊做法 141/141 逐列一致，再正式切換。

**第四階段｜每日營運。** 用 macOS launchd 排程，每天收盤後自動抓取。每晚做健康檢查：資料是否最新、排程是否失敗、備份是否過期；每週備份資料庫。T86 當天還沒公布時，每 20 分鐘重抓一次。每日行情抓取失敗時，等 5 分鐘重試，最多 3 次。期交所的台指期日盤與夜盤也每天更新。

**第五階段｜補 Vibe-Edge 要的資料。** 依 Vibe-Edge 的需求補上多種歷史資料：處置股與注意股歷史、上市與上櫃下市歷史、休市表、面額變更與分割、庫藏股與減資事件。每張表都登記進資料層目錄。

QuantaAlpha 的台股基準測試跑通了，但結果不理想：扣成本後的超額報酬年化為 −11.8%，資訊比率 −1.04。
