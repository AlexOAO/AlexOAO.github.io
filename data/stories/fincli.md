## 結果

**FinCLI 每天收盤後，會自動抓取台股的原始資料，存進 PostgreSQL 資料庫；Vibe-Edge 的資料層就是從這裡拿資料。** 核心是 `tw-fin-scraper` 這個命令列工具（在終端機下指令執行的程式）。它目前接了 23 個資料來源，包括證交所、櫃買中心、公開資訊觀測站（MOPS）、TEJ 和期交所。

## 為什麼要做

量化研究需要原始、查得到出處的資料，但很多台股資料沒有現成的 SDK 套件可以直接用。像處置股、注意股、法說會和三大法人買賣超，都只能一個一個去串官方 API 或網頁。

我也定了一條規則：抓資料的這一層不改資料。來源給什麼就存什麼，清理交給後面的流程。如果抓的時候就自作主張轉換，後面的人就再也拿不回原始數字。

## 我的角色

獨立開發 `tw-fin-scraper` 和 `yf-history`。

同一個資料夾裡的 QuantaAlpha 不是我寫的。它是外部的開源專案（[QuantaAlpha/QuantaAlpha](https://github.com/QuantaAlpha/QuantaAlpha)），也沒有放進 FinCLI 的版本控制。我只改了兩個設定檔，讓它改用台股資料，跑了一次基準測試。

## 我怎麼做

**第一階段｜先拿到資料。** 我先用 yfinance 補齊 51 檔台股從 2019-09-02 到 2026-08-31 的歷史資料，共 1,699 個交易日，存成原始 CSV 檔。另外也串接了證交所 T86 的三大法人買賣超資料。補資料時遇到來源限制抓取速度，我把 HTTP 428 也當成 429（請求太頻繁）處理，用指數退避的方式重試：每次失敗後，等待的時間就拉長一些。

**第二階段｜擴大來源並落地資料庫。** 我一次新增 8 個資料來源，PostgreSQL 擴大到 26 張表，並加上 `--resume`，中斷後可以從斷點接著抓。證交所官方 OpenAPI 的 143 個端點全部串好，櫃買中心的 225 個 OpenAPI 端點也全部串好。TEJ 則用瀏覽器自動化登入，把 238 張表的快照存成底稿。

**第三階段｜用規格取代手寫程式。** 我刪掉約一萬行手寫程式，改成「規格檔 + 通用引擎」：每種資料只要寫一份規格，由同一個引擎去抓。證交所的 141 種 OpenAPI 資料，原本是一個一個手寫的。切換前，我先確認新舊做法抓到的資料 141/141 逐列一致，才正式換過去。

**第四階段｜每日營運。** 我用 macOS 內建的排程工具 launchd，讓它每天收盤後自動抓資料。每晚做一次健康檢查：資料是不是最新的、排程有沒有失敗、備份有沒有過期；資料庫每週備份。T86 當天還沒公布時，每 20 分鐘重抓一次。每日行情抓失敗時，等 5 分鐘再試，最多 3 次。期交所的台指期日盤和夜盤，也每天更新。

**第五階段｜補 Vibe-Edge 要的資料。** 我依照 Vibe-Edge 的需要，補上好幾種歷史資料：處置股和注意股的歷史、上市和上櫃公司的下市歷史、休市日、面額變更和股票分割、庫藏股和減資事件。每張表都登記進資料層的目錄。

QuantaAlpha 的台股基準測試有跑完，但結果不好：扣掉交易成本後，超額報酬一年是 −11.8%，資訊比率 −1.04。
