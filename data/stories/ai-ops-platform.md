## 結果

**我做了一個 AI 營運平台，把四個 Agent 的營運、成本、效能和治理收在同一個地方，並把同一位客戶在四個 Agent 走過的路串成一條旅程。** 平台也把每個 Agent 的業務規劃書（預期）和實際營運數字放在一起比，直接算出達成率。

- 四個 Agent 原型的實際資料都已經接上，平台每分鐘收一次。
- 同一位客戶從獲客、徵審、服務到經營，在平台上可以看到完整的時間軸。平台看不到身分證字號。
- 第一次比較預期和實際時，就抓出三個「口徑」問題：預期和實際用了不同的算法，數字才會差好幾倍。修正後，平台把真正落後的 Agent 列進「需要檢討」。

## 為什麼要做

**四個 Agent 各有自己的後台，主管最在意的問題卻分散在四個地方。** 這些 AI 值不值得？花了多少錢？跑得穩不穩？同一個客戶從獲客到經營，走了哪些路？要回答這些問題，以前得打開四個後台，各自換算再拼起來。

[四大 AI Agent](project.html?id=agent-cost-roi) 的成本效益框架，和 [AI 營運成效 Dashboard](project.html?id=ai-ops-dashboard) 的五個面向，都已經定好「要看什麼」。這個平台要回答的是「怎麼真的看到」：資料從哪裡來、怎麼對齊、怎麼比。

## 它做什麼

**服務對象。** PMO、業務單位主管和 AI 專案的管理者。它不面對客戶。

**五個模組：**

- **營運總覽：** 四個 Agent 放在同一張表，看採用、品質、效益、成本、風險五個面向。
- **客戶旅程：** 旅程流向、轉換漏斗、各段之間停留多久，以及單一客戶的完整時間軸（客戶 360）。
- **成本與效能：** 單件成本、三年基準和實現比率；延遲、錯誤率、可用率和告警。
- **業務規劃：** 投資組合，以及每個 Agent 的業務規劃書。每個數字都並列預期、實際和達成率。
- **治理：** 上線前九格檢核、護欄攔截統計、AI 和人工判斷的一致率，以及設定變更的時間軸。

**兩個網址，兩種人。** 報表網址只能看，不能改任何東西；管理網址才有價格表、告警規則和帳號。兩個網址都要先通過 Zero Trust 登入。

## 我的角色

我主責設計和實作：資料交換格式、平台本身，以及四個 Agent 的匯出功能。

## 我怎麼做

**第一階段｜問題定義。** 平台只做三件事：收資料、算指標、比較。它不改任何 Agent 的規則或資料。業務規則、基準和護欄，都留在各 Agent 自己的後台管。這樣平台停了，Agent 照常運作；Agent 換了，平台也不用改。

**第二階段｜框架設計。** 我先定一份四個 Agent 都照著做的資料交換格式，而不是讓四個 Agent 共用同一套程式：

- **每個 Agent 開一個唯讀的出口。** 提供事件、每日指標、治理資訊和業務規劃書，平台定時去拉。出口要有金鑰，而且只接受內部呼叫，從公開網址呼叫一律被拒絕。
- **客戶身分用雜湊值，不用身分證字號。** 四個 Agent 用同一把鑰匙，把客戶 ID 算成一串雜湊值。同一位客戶在四邊算出來的值一樣，平台就能把紀錄串起來，但從雜湊值反推不回身分證字號。畫面上只顯示遮蔽後的 ID。
- **成本用同一個口徑。** 各 Agent 只回報用量：模型處理的文字量、OCR 秒數、通話秒數。平台再用同一份價格表換算成新台幣，四個 Agent 才比得起來。
- **只用真實資料。** 平台不產生任何模擬數字。樣本少於 5 件時只顯示件數，不顯示百分比，避免看起來比實際精準。

**第三階段｜實作與驗證。** 我做了平台本身，也替四個 Agent 加上出口。驗證有三層：

- 每個 Agent 都要通過格式檢查，並確認從公開網址呼叫一定被拒絕。
- 我用同一位測試客戶，實際走完四個 Agent：在貸款助理申辦、匯出案件包，交給智能徵審辨識和覆核，再接聽一通客服電話，最後在智富管家問一題。平台把這四段串成同一位客戶的旅程，也接起了案件包，成本也算進去了。
- 走這一遍時，我發現智能徵審的收件時間是另一種時區格式，平台會把「收件」排在「申辦」前面。兩邊都改了，並加上測試。

**第四階段｜業務規劃：預期與實際。** 每個 Agent 的業務規劃書由它自己的後台維護，經辦編輯、主管核准，平台只讀已核准的版本。規劃書有四期：2026 試行期和 2027 到 2029。平台把年度計畫依天數換算到選定的期間，再和實際並排。

第一次比較時，有三個數字差了好幾倍，但問題都不在計算，而在口徑：

- **貸款助理的效益：** 實際算的是「所有 AI 協助的申請」，預期算的卻是「其中由 AI 促成的那 18%」。
- **客服助理的成本：** 規劃書的單通成本沒有算進語音辨識，但實際成本是依通話秒數計價。
- **智能徵審的成本：** 歷史資料只記了金額，沒有記用量，平台換算後幾乎是零。

所以我在規劃書加上「效益口徑」，讓預期和實際用同一種成果、同一個單價來比；成本也拆成變動成本和固定成本。修正後的規劃書照正式流程送審核准，成為第 2 版。現在平台會把真正落後的 Agent 列進「需要檢討」，例如貸款助理的促成達成率低於它自己訂的 80% 門檻。
